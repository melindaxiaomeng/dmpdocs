# DMP 系统运营手册

> 本文档面向**运营人员**，介绍 DMP 系统各功能模块的操作方法。
> 适用于技术重构版前端（4 步向导式数据源、结构化广告系列表单、报表与人群关联等）。

---

## 一、系统概述

DMP（数据管理平台）用于管理广告投放相关的**数据源、人群包、广告系列**等核心资源。

- **登录地址**：由技术人员部署后提供（默认端口 3000）
- **浏览器建议**：Chrome / Edge 最新版
- **登录**：使用分配的账号密码登录；登录态过期会自动跳回登录页

左侧为功能导航菜单，右侧为操作区。菜单项包括：仪表盘、广告活动、广告主管理、数据源管理、数据源报表、人群包管理、人群包-活动关联、标准字段、标准事件、用户管理。

---

## 二、仪表盘

登录后默认进入，展示系统核心数据概览（数据源数量、人群包数量、广告系列数量等）。

## 三、数据源管理（核心）

> 路径：左侧菜单 → **数据源管理**

数据源是广告投放的数据入口，配置「如何接收和处理数据」。新建时使用 **4 步向导**，每一步都可「上一步 / 下一步」，最后一步「提交创建」。

### 第 1 步：基本配置

| 字段 | 必填 | 说明 | 可选项 |
|------|------|------|--------|
| 名称 | ✅ | 数据源识别名 | 文本，最长 100 |
| 来源类型 | ✅ | 数据来源种类 | `RTB` / `MMP` / `SDK` / `File` |
| 接入方式 | ✅ | 数据接入手段 | `API` / `Postback` / `Upload` |
| 状态 | — | 默认「启用」 | `禁用(0)` / `启用(1)` / `异常(2)` |
| 鉴权 Token | — | 接口鉴权令牌 | 文本，选填 |
| IP 白名单 | — | 仅允许白名单内 IP 接入 | 支持单 IP 或 `10.0.0.0/24` 段，可多条 |

### 第 2 步：字段映射规则

- **数据根节点**：JSON 数据的根路径，如 `payload` 或 `payload.data`，留空表示最顶层。
- **需解析的 JSON 字符串字段**：填写需要从字符串里再解析出 JSON 的字段名（如 `event_value`），可多条。
- **字段映射（标准字段 → 源字段路径）**：把系统的「标准字段」对应到对方数据里的「字段路径」。例如标准字段 `device_id` 对应源路径 `device.advertising_id`。至少需配置一条完整映射才能进入下一步。

### 第 3 步：清洗规则

- **数据模式（Schema）**：定义每个字段的类型与约束。选择标准字段后，类型（string/int64/float/bool）、是否必填会自动带出；字符串可勾选 Trim，数值可填 Min/Max，可填默认值。
- **标准化器（Standardizers）**：将原始数据标准化。**类型只能从以下 4 个里选，且每个最多用一次**：
  - `device_identity`（设备身份）：normalize_raw / normalize_to_md5 / normalize_to_sha256
  - `network_ip`（IP/网络）：extract_clean_ip
  - `event_time`（事件时间）：to_utc_millis / string_to_utc_millis（可选填源时区）
  - `geo_country`（地域/国家）：to_iso_alpha2
- **业务逻辑**
  - **事件映射**：开启后，配置「源字段 → 标准事件」的映射字典，以及未匹配时的处理（`keep` 保留 / `drop` 丢弃 / `set_default` 设默认值）。
  - **丢弃过滤规则（Drop Filters）**：设置丢弃条件。
    - 字段名 + 运算符（`is_empty` 为空 / `is_not_empty` 非空 / `in` 在白名单 / `not_in` 在黑名单 / `older_than_days` 早于 N 天 / `in_the_future_hours` 超前 N 小时）
    - 当运算符为「为空 / 非空」时，**无需填写值**；其余需填阈值。

### 第 4 步：下游策略

- **去重策略（Deduplication）**
  - 策略：`sliding_window` 滑动窗口 / `periodic` 自然周期
  - 滑动窗口：填窗口秒数、Redis TTL 秒数
  - 自然周期：填周期（`natural_day` / `natural_hour`）、时区
  - 去重 Key：参与去重的字段名，可多条
  - 重复处理：`drop_silently` 静默丢弃 / `route_to_dlq` 路由至死信队列
- **聚合风控策略（Aggregation）**：开启后可添加多个监控窗口
  - 名称、聚合 Key、指标（`count` / `sum_revenue`）、窗口秒数
  - 阈值规则：运算符（> >= == < <=）+ 阈值 + 命中动作（`block_s2s` 阻断 S2S / `flag_suspicious` 标记可疑）+ 通知 Webhook

> 第 2~4 步均为可选。配置完成后点「提交创建」。

### 编辑 / 停用数据源

- **编辑**：操作列「编辑」按钮（同样以向导形式）。
- **停用**：将状态改为「禁用」或「异常」即可暂停接收数据。
- **删除**：操作列「删除」（不可恢复，谨慎）。

## 四、广告活动（核心）

> 路径：左侧菜单 → **广告活动**

广告系列是投放核心单元，一个广告主可有多条广告系列。

### 新建广告活动字段说明

| 字段 | 必填 | 说明 | 备注 |
|------|------|------|------|
| 活动名称 | ✅ | 系列名称 | 最长 255 |
| 应用包名 | ✅ | APP 包名（如 `com.xxx.app`） | **技术版新增必填项** |
| 关联 APP 名称 | — | APP 展示名 | 最长 128 |
| 广告主 | ✅ | 选择广告主 | 下拉选择 |
| 广告主侧 Campaign ID | — | 广告主系统内的 ID | 选填 |
| 目标平台 | ✅ | `Android` / `iOS` / `Web` | |
| 状态 | — | 默认「待审核」 | 见下方枚举 |
| 目标国家 | ✅ | 投放国家代码，逗号分隔 | 如 `US,JP,KR` |
| 结算模式 | ✅ | `CPI` 按安装 / `CPE` 按事件 | |
| 结算事件 | — | 触发结算的事件名 | 如 `install` |
| 结算单价 | ✅ | 单次转化单价 | **单位：USD（美元）** |
| 归因窗口(h) | — | 点击后有效归因时长 | 默认 24 小时 |
| 日转化上限 | — | 每日最多转化数 | 0 = 无限制 |
| 总转化上限 | — | 系列生命周期最多转化数 | 0 = 无限制 |
| 点击追踪链接 | ✅ | 点击监测 URL | 最长 1024 |
| 触发源 | — | 允许触发的流量源 | 默认 `ALL` |
| 毛利控制底线 | — | 最低毛利比例 | 以百分比填写，默认 10% |
| 延迟策略 | — | 反欺诈延迟发送策略 | **表单选择，无需写 JSON**（见下） |

### 延迟策略（运营填表即可，不用写代码）

- **立即发送**：数据实时转发。
- **离散随机延迟**：填最小 / 最大延迟（分钟）。
- **自适应行为模拟**：选分布模型（`normal` 正态 / `long_tail` 长尾）+ 离散方差。
- **自适应热力图**：选目标时区 + 填写 24 小时权重（24 个逗号分隔的数值）。

> 说明：旧版这里是一个 JSON 文本框，运营难以填写；技术版已改为上述下拉 + 条件输入，普通运营可直接操作。

### 状态枚举

`0 暂停` / `1 运行中` / `2 已结束` / `3 待审核` / `4 熔断`（毛利风控触发时自动熔断）

### 编辑 / 暂停

- 操作列「编辑」可改任意字段；「状态」切换为「暂停」即停投。
- 列表支持按状态/平台/结算模式筛选，支持启停切换。

## 五、广告主管理

> 路径：左侧菜单 → **广告主管理**

管理投放客户（广告主）基本信息：名称、联系人、联系方式、状态（活跃 / 停用）。新建广告活动前请先确保广告主已创建。

## 六、人群包管理

> 路径：左侧菜单 → **人群包管理**

人群包用于精准定向，把用户分组。

| 字段 | 说明 |
|------|------|
| 人群包名称 | 便于识别，如 `高价值用户-2024Q2` |
| 描述 | 人群说明 |
| 规则配置 | 人群筛选条件（由技术人员协助配置） |

创建后，人群包可用于「人群包-活动关联」模块与广告活动绑定。

---

## 七、人群包-活动关联

> 路径：左侧菜单 → **人群包-活动关联**

将已创建的人群包关联到具体广告活动，实现定向投放或排除。按页面提示选择「人群包」与「广告活动」并建立关联即可。

---

## 八、标准字段 / 标准事件

> 路径：左侧菜单 → **标准字段** / **标准事件**

系统级标准化定义，保证不同数据源的数据能统一处理：

- **标准字段**：如 `device_id`、`ip`、`timestamp` 等系统标准字段（含类型、是否必填）。
- **标准事件**：如 `install`、`purchase`、`login` 等系统支持的事件。

> ⚠️ 这两个模块通常由**技术人员维护**，运营一般只需了解，无需修改。数据源的「字段映射」「Schema」正是从这里选择标准字段。

## 十、用户管理

> 路径：左侧菜单 → **用户管理**

管理系统登录账号：新建用户（用户名、密码、绑定角色）、停用用户、重置密码等。

> 注：本版前端菜单仅含「用户管理」；角色/权限的细粒度配置若需开放，由技术人员在后台补充。

## 十一、常用操作流程

### 11.1 新建一个完整投放

1. 在「广告主管理」确认广告主已存在
2. 在「数据源管理」用 4 步向导配置数据接入（重点配好字段映射与清洗规则）
3. （可选）在「人群包管理」创建目标人群
4. 在「广告活动」新建广告系列，填好应用包名、目标国家、结算单价、点击链接、延迟策略
5. 状态置为「运行中」开始投放

### 11.2 暂停某个广告系列

进入「广告活动」→ 找到目标 → 编辑 → 状态改为「暂停」→ 保存。

### 11.3 临时止付可疑数据

进入「数据源管理」→ 编辑 → 第 4 步开启「聚合风控」并设置阈值动作，或将数据源状态改为「异常」暂停接收。

---

## 十二、注意事项

> ⚠️ **删除操作不可恢复**，执行前务必确认  
> ⚠️ **状态字段**控制数据是否生效；新建数据源后确认状态为「启用」  
> ⚠️ **应用包名 / 广告主侧 Campaign ID** 需与广告主系统保持一致，否则数据无法关联  
> ⚠️ **结算单价单位为 USD（美元）**，填写时注意币种  
> ⚠️ 标准化器**只能选 4 个固定类型且不可重复**；选择后类型即固定，不能自定义名称  
> ⚠️ 丢弃过滤规则中，运算符为「为空/非空」时**不要填值**

## 十三、常见问题

**Q：新建数据源后没数据？**  
A：检查状态是否为「启用」；检查 IP 白名单是否限制了发送方 IP；检查第 2 步字段映射是否正确。

**Q：广告活动显示「运行中」但没投放？**  
A：检查关联数据源是否正常、每日/总转化上限是否已达、点击链接是否可达。

**Q：表单提交报错？**  
A：检查必填项（活动名称、应用包名、目标国家、结算单价、点击链接等）是否齐全；字段格式是否正确。

**Q：延迟策略 / 高级配置还要写 JSON 吗？**  
A：不用。技术版已改为下拉 + 条件输入，运营直接填表即可。

## 附：技术对接要点（供研发参考）

- **前端技术栈**：React 19 + antd 6 + react-router 7 + zustand 5 + Vite 8
- **API 前缀**：`/api/v1`（请求拦截器自动附带 `Authorization: Bearer <token>`）
- **响应约定**：`code === 0` 为成功，非 0 弹错误提示
- **本地代理**：开发环境 `/api` → `http://10.7.94.8:8080`（见 `vite.config.ts`）
- **构建**：`npm install` → `npm run build`，产物在 `dist/`
- **待技术补全**：`Publisher` / `Creative` 两个模块在构建产物（dist）中存在编译 chunk，但**源码未随包提供且未挂入路由/菜单**，当前 UI 不可访问，需技术确认是否补发源码。
